# 画像（来自 2026-01-05 一天的合成轨迹）

证据只有一天、一类任务，以下都是初步结论。

## 工作习惯

- **取数 → 写 → 回看源表 → 保存。** 两次写周报都是先从 Excel 复制数字粘到文档里，写完后切回同一张表停留约 15 秒、
  只滚动不复制，再回文档（`2026-01-05:S001`、`S006`）。核对发生在写完之后、保存之前。
- **先保存一版，离开，回来改。** 两次都是第一次保存后去看邮件，约 5 分钟后回到文档，连按撤销并大量删除重写，再保存
  （`S002`+`S003`、`S007`+`S008`）。第一版不是终稿。
- **保存终稿前通读。** 终稿保存前各有约 22 秒只滚动不打字（`S004`、`S009`）。
- **发送前停顿。** 邮件写完到发出之间约 20 秒无输入（`S005`、`S010`）。
- **给 agent 下任务很短。** 一句话起头（“根据 metrics_W41.csv 帮我起草周报”，16:00:00），要求在后续几轮里补。

## 验收风格

- **数字必须与源文件一致，而且会追问是否核对过。** 第一版周报里收入数字与 csv 不一致（两周都是相邻两位写反），
  回来后改掉（`S002`、`S007`，对比 blobs 里的两版）；对 agent 的草稿直接问“数字你核对过 csv 吗？”（`S011`）。
- **不要形容词和总结性的话，只列数字。** 对 agent 明说（`S011`）；自己的第一版里有“本周表现不错，各项指标稳步增长，团队状态很好”，
  终稿删掉了（`S002`、`S007` 的两版对比）。
- **要写数据来源。** 终稿比第一版多一行“数据来源：metrics_Wxx.csv”（两次都是）；对 agent 也要求“最后加一行数据来源，写文件名”（`S012`）。
- **打回时一次说清原因，通过时很短。** 打回是一句话带两条理由（`S011`），通过只有“可以”（`S013`，回复后 15 秒）。
- **查得全。** 三个数字的报告，写完回看源表、保存前通读、发送前停顿，都在。

证据偏弱：只有一个对话会话；“发送前停顿”也可能只是在找收件人。
