# 周指标周报

## 何时使用

有一份当周的指标 csv，需要一份可以直接发出去的周报。

## 输入

- `metrics_<周次>.csv`：两列 `metric,value`，每行一项指标。

## 产出

- `weekly_<周次>.md`：标题、每项指标一行、末尾一行数据来源。

## 硬性约束

1. 报告里的每个数字都必须逐字来自 csv，不四舍五入，不换单位，不心算派生值（环比、合计）除非 csv 里有。
2. 只列数字。不写评价、总结、展望，不加形容词。
3. 末尾写明数据来源，写 csv 的文件名。
4. 不发送邮件。只产出文件，发不发由本人决定。

## 必须停下的情况

- csv 不存在、为空，或缺少上一期报告里有的指标。
- 某个值不是数字，或与列名明显不符（例如流失率大于 100）。

## 步骤

1. 读 csv，得到周次（取自文件名）和全部 `metric → value`。
2. 写 `weekly_<周次>.md`：
   - 第一行 `# 周报 <周次>`。
   - 每项指标一个列表项，顺序与 csv 一致。收入类加 `$` 前缀，百分比类加 `%` 后缀，数值本身照抄。
   - 空一行后写 `数据来源：<csv 文件名>`。
3. **检查点（写完后、交付前）**：重新打开 csv，把报告里的数字逐个与源值对一遍。
   相邻数位写反是出过的错，要逐位看，不要凭印象。
4. 通读一遍全文，删掉任何不带数字的句子。

## 交付前验收

运行 `python verify.py --input <输入目录> --output <产出目录>`。
FAIL 的修掉重跑；TODO 的条目按 rubric 逐条自评，并把结论写进交付说明。
按输出里的 `policy` 行事：全量核对，最多修两轮，源数据有问题就停下问人。
