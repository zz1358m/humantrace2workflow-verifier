# TASK：按预填的个人风格，为一个合成样本生成访问记录

当前目录有一份样本草稿 `{{stub}}`，里面已经填好：`persona`、`purpose`、`rubric`、`style`（这个人的个人风格，是生成条件）、
`task`（留出的任务实例和参考产出）。缺的是 `records`（这个人过去留下的访问记录）和 `workdir`（他的工作目录快照）。
同目录的其他 `*/sample.yaml` 是写好的例子，格式照它们来。

把 `records` 和 `workdir` 补进 `{{stub}}`：

- `records` 下按来源分：`claude`、`codex`（会话列表，每个会话有 `session`、`cwd`、`turns`），`shell`、`browser`、`chat`（事件列表）。
  每条带 `at: "YYYY-MM-DD HH:MM:SS"`。turn 的形式：`{at, user}`、`{at, assistant, tools}`、`{at, abort: true}`、`{at, deny: <工具名>}`。
- **每一条风格都必须在记录里留下痕迹**，而且是这个人自然会留下的那种：打回 agent 的草稿并说出原因、追问有没有核对、
  在聊天里对同事说过类似的话、shell 里手工核对的命令、中断或拒绝 agent 的某个动作。受某条风格影响的记录打上 `from: [<风格 id>]`。
- 不要把风格条目原话照抄进记录。真人不会背诵自己的标准，只会在某次具体的事上表现出来；同一条风格最好在不同来源里出现两次。
- 至少覆盖这个任务过去的两次发生，不要出现 `task` 里留出的那一次的任何内容。
- 掺入与风格无关的日常记录（别的任务、闲聊、浏览），大约占一半，否则太容易。
- `workdir` 放过去几次的输入文件和产出；至少有一份被他改掉的草稿（文件名带 `_v1`）和对应的终稿。
- 不出现真实的人名、公司、邮箱、电话。

写完运行 `python -m ht2wv bench validate .`（在样本目录里），必须输出 ok。

最后一条消息只写：各来源各写了几条记录、每条风格出现在哪些来源。
